# 要件の確定度整理 v0.1

**作成日：2026年10月12日**

**対象資料：** [要件定義書(仮).md](./要件定義書(仮).md)、[IT担当者の役割.md](./IT担当者の役割.md)
**位置付け：** 担当者ヒアリング前の分類。ここでの「確定済み」は、現行MDに確定事項として記された内容を指す。現場での最終承認や技術的な実現保証を意味しない。

## 分類の基準

| 分類 | 意味 | 詳細定義での扱い |
| --- | --- | --- |
| 確定済み | 現行MDで明示され、矛盾なく仕様化できる事項 | 詳細定義の前提とする。変更する場合は理由と承認者を記録する |
| 仮決め | MVP案・想定・具体案として書かれた事項 | 画面・データ案に反映するが、確定扱いにしない |
| 要ヒアリング | 現場の運用、資料の現物、権限者の判断が必要な事項 | 質問と暫定案を残し、回答後に確定する |
| 要技術検証 | 端末・認証・保存・運用基盤で実現性を確かめる事項 | 受入条件を先に定め、試作・実機試験・運用確認後に方式を選ぶ |

## 要技術検証

| ID | 検証すること | 合格条件の例 |
| --- | --- | --- |
| T-01 | iPhoneで全利用者分のPDF・評価・ニーズを保存し、通信なしで閲覧できるか | 実際のPDF容量で取得・再起動・長期未接続を試し、表示できる |
| T-02 | 1時間経過後のFace ID／端末パスコードによるオフライン再認証 | オフライン・アプリ再起動・認証失敗を含めて要件どおり制御できる |
| T-03 | 端末パスコード必須、端末固有の鍵、暗号化、バックアップ除外 | iOS実機で保護と機種変更時の再取得を確認できる |
| T-04 | 更新失敗時に旧版を保持し、取得状態を正しく表示できるか | 通信断・容量不足・破損ファイルで旧版を失わない |
| T-05 | 紛失・退職・利用終了時のオンライン停止と再接続後の端末データ削除 | 停止後の再接続で閲覧不可となり、削除結果を確認できる。オフライン端末の即時削除は前提にしない |
| T-06 | Google本人確認、Passkeyの要否、初期IT担当者の安全な紐付け、再認証 | 権限のない自主登録ではIT権限を得られない |
| T-07 | PDFの3ページ目開始、拡大、アプリ外への保存・共有機能の扱い | iPhoneと将来対象のAndroidで期待どおり動く |
| T-08 | バックアップの復旧と削除済み記録の再公開防止 | 24時間以内の更新損失、1か月以内の復旧、削除期限を満たす運用を示せる |
| T-09 | オフライン閲覧履歴の保護、重複なく再送する方法 | 通信断・再送・端末時刻変更・端末消失時の限界を確認する |

## 整合確認が必要な記述

1. 要件定義10章の「最初のIT担当者は本人が自主的に登録する」と「事前に決めた1つの職員アカウントだけへIT権限を付ける」は両立可能だが、最初の本人確認と紐付け方法が未定。自主登録だけでIT権限を得る仕様にはしない。
2. IT担当者の役割資料には、サービス管理者不在時にIT担当者が自身の後任を指定できるとある。要件定義10.1章はさらに両者不在時の代理を定める。詳細定義では後者も含め、代理の発動判断と証跡はH-07で確認する。
3. 要件定義6.3章は過去の正式記録を保持する一方、11章では正常更新後の旧版の保存期間が未確定。利用者別の正式記録と、それ以外の一時ファイル・組織共通PDFの版を分けて定義する。
4. 要件定義13章は初期移行をIT担当者の登録で完了するとする一方、通常更新では公開前確認を求める。詳細定義では初期移行と通常更新を別フローにする。
